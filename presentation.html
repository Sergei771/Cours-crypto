Contexte du Projet

Le concept TeaRoom

TeaRoom est la dénomination sociale d'une entreprise reposant sur un salon de thé. Le "TeaRoom" possède une application web full-stack permettant aux clients de :

  • Découvrir leurs produits signatures
  • Réserver une table pour le midi
  • Commander des gâteaux et payer sur place

L'entreprise a sollicité une solution pour renforcer la sécurité des données, en particulier dans le cadre du respect du RGPD, afin d'éviter toute fuite de données sensibles.

session_controller.py 
from anvil.js.window import sessionStorage
import anvil.http

BASE_URL = "https://tearoombackend.onrender.com"

def login(email, password):
    res = anvil.http.request(
        f"{BASE_URL}/session/login",
        method="POST",
        data={"email": email, "password": password},
        headers={"Content-Type": "application/json"},
        json=True,
        use_service_worker=False
    )
    if res["success"]:
        sessionStorage.setItem("jwt_token", res["token"])
    return res

def get_user_info():
    token = sessionStorage.getItem("jwt_token")
    if not token:
        return None
    try:
        res = anvil.http.request(
            f"{BASE_URL}/session/me",
            method="GET",
            headers={"Authorization": f"Bearer {token}"},
            json=True,
            use_service_worker=False
        )
        if res["logged_in"]:
            return res["user"]
        return None
    except anvil.http.HttpError as e:
        print("Token invalide ou expiré :", e.status)
        sessionStorage.removeItem("jwt_token")
        return None

def logout():
    sessionStorage.removeItem("jwt_token")

Mécanismes de sécurité implémentés

Authentification JWT

Utilisation de tokens JWT (JSON Web Tokens) pour l'authentification des utilisateurs avec une vérification à chaque requête protégée.

db.py (middleware d'authentification) 
def require_jwt(f):
    @wraps(f)
    def decorated_function(*args, **kwargs):
        auth_header = request.headers.get("Authorization", "")
        if not auth_header.startswith("Bearer "):
            return jsonify({"error": "Authorization header missing"}), 401

        token = auth_header.split(" ")[1]
        try:
            payload = jwt.decode(token, JWT_SECRET, algorithms=["HS256"])
        except jwt.ExpiredSignatureError:
            return jsonify({"error": "Token expired"}), 401
        except jwt.InvalidTokenError:
            return jsonify({"error": "Invalid token"}), 401

        request.user_id = payload["user_id"]
        request.is_admin = payload.get("is_admin", False)
        return f(*args, **kwargs)

    return decorated_function

Chiffrement AES de la facture

Utilisation d'AES pour chiffrer la facture, avec un vecteur d'initialisation (IV) et une clé secrète partagée.

encrypt_pdf 

def encrypt_pdf(pdf_data):
    """Chiffre les données PDF avec AES"""
    cipher = Cipher(algorithms.AES(AES_KEY), modes.CBC(AES_IV), backend=default_backend())
    encryptor = cipher.encryptor()
    pad_length = 16 - (len(pdf_data) % 16)
    padded_data = pdf_data + bytes([pad_length]) * pad_length

    encrypted_data = encryptor.update(padded_data) + encryptor.finalize()
    return encrypted_data

Défis et limitations

Menace de l'informatique quantique

Les algorithmes quantiques comme l'algorithme de Shor pourraient casser les systèmes de chiffrement asymétriques actuels. L'utilisation d'Argon2 et la préparation à la migration vers des algorithmes post-quantiques sont des mesures d'atténuation.

Équilibre entre sécurité et performance

Le renforcement de la sécurité (comme l'augmentation du coût du hachage Argon2) peut affecter les performances. Un équilibre est maintenu pour assurer une expérience utilisateur fluide tout en protégeant les données sensibles.

Améliorations de sécurité

Authentification multi-facteurs (MFA)

Ajouter une authentification à deux facteurs pour renforcer la sécurité des comptes, notamment pour les administrateurs.

Exemple d'implémentation avec TOTP (Time-based One-Time Password) :

mfa.py (proposition) 
import pyotp

def generate_totp_secret():
    """Génère un secret pour TOTP"""
    return pyotp.random_base32()

def verify_totp(secret, token):
    """Vérifie un code TOTP"""
    totp = pyotp.TOTP(secret)
    return totp.verify(token)

def get_totp_uri(secret, email, issuer="TeaRoom"):
    """Génère l'URI pour les applications d'authentification"""
    totp = pyotp.TOTP(secret)
    return totp.provisioning_uri(email, issuer_name=issuer)

Chiffrement homomorphe pour données sensibles

Utiliser le chiffrement homomorphe pour les données sensibles permettrait de réaliser des opérations sur les données chiffrées sans avoir besoin de les déchiffrer.

Cela offrirait une couche supplémentaire de protection même en cas de compromission de la base de données.

Cela garantirait la sécurité à long terme des données, même face à l'émergence d'ordinateurs quantiques puissants.
